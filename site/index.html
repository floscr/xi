What is xi?

Xi is an agent harness built in ClojureScript and Bun, inspired by Pi. It runs your coding agent in the terminal and ships with a ready-made web UI that connects to the very same sessions — so a conversation started at your desk can be picked up in the browser, mid-stream, without losing a token.

Pure core

Handlers, not spaghetti

Every feature is a pure reducer over one atom. No local component state, no hidden mutation. Effects are plain data, interpreted at the edge.

Providers

Bring your model

Claude via the Agent SDK, or Ollama locally. A provider is just a map with a start-turn! — routing picks by name or explicit choice.

Sessions

Pi-compatible history

Conversations persist as JSONL on disk, resumable with /resume. Standalone is simply "not connected" — same shape, same code.

Start in the terminal.
Land in the browser.

The web UI isn't a bolted-on dashboard — it joins the same room, the same events. Kick off a refactor in the TUI, stand up, and open localhost:7474 on any device: the conversation is already there, still streaming. Reply from the browser and the terminal follows. A clean hand-off, in both directions.

One agent, three faces.

The TUI, the WebSocket server, and the browser client are all assemblies of the same pure handlers. Pick the surface — the brain doesn't change.

xi

Terminal TUI

A full-screen terminal client with editor, syntax highlighting, and markdown — rendered from state, change-gated to one paint per burst.

xi server

Rooms over WS

A Bun WebSocket server hosting multiple rooms. The wire protocol is the event maps, serialized as EDN. Rooms auto-destroy when idle.

localhost:7474

Web client

A Replicant browser client that mirrors the server exactly — same reducers, same order. Works offline with a localStorage cache.

Everything is an event.

Prompts, agent tokens, slash commands, dialogs, room switches, even renders — they all flow through one FIFO dispatch queue, one event at a time. Handlers return new state and effect data. Taps observe every step, which is how broadcast, caching, and the event log all work.

xi.core.events 
;; a handler is (fn [state event])
(defn handle-text-delta
  [state {:keys [text]}]
  {:state
     (append-entry state text)
   :effects
     [[:render/schedule]]})

;; the wire protocol IS the event
{:type :agent/text-delta
 :room-id "a1f0"
 :text "Reading the file…"}

Extensions are just data.

An extension is a plain map — handlers, effects, tool gates, commands, keybindings. No registration atoms; they're composed at assembly time. Add a tool, gate a call, or badge the prompt without touching the core.

xi.ext.commit 
{:id :commit
 :commands
 {"commit"
  (fn [state args]
    {:effects
     [[:git/commit args]]})}

 :tool-gate
 (fn [call ctx]
   ;; allow / modify / block /
   ;; short-circuit with a result
   call)}
